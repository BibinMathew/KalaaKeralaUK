# Free client review: Render + Supabase

This deployment is for review, with synthetic member data and Stripe test payments. No accounts or live deployment have been created by this package.

## 1. GitHub
Extract the ZIP. Upload the CONTENTS of kalaa-kerala to a private GitHub repository: manage.py and render.yaml must be at the repository root. Include hidden .github and .gitignore files. Never upload .env, databases or credentials.

## 2. Supabase
Create a Free project at https://supabase.com/dashboard with a strong database password. Pick a European region near your Render service.

Before migrations, disable the project's Data API in its API settings. This Django app accesses PostgreSQL directly and does not use Supabase REST/GraphQL. Django tables contain private member and admin information and must not be exposed through the Data API. Do not enable it later without reviewing grants and RLS on every application table.

Click Connect and select **Session pooler**, port 5432 (not transaction mode 6543). Copy its exact URI, replace the password placeholder with your URL-encoded database password, and append `?sslmode=require` (or `&sslmode=require` if there is already a query). Use this as DATABASE_URL in Render. Do not guess the pooler hostname. Session pooler works over IPv4. For stronger TLS identity verification, configure the Supabase root certificate with sslmode=verify-full and sslrootcert.

In Storage, create a **private** bucket named `event-photos`. Set allowed MIME types to image/jpeg, image/png, image/webp and maximum file size 10 MB. Public images are served using signed URLs generated by Django. Generate server-side S3 credentials in Storage settings; copy the access key, secret key, endpoint and region exactly. These are S3 keys, not the anon/publishable/service-role API keys.

## 3. Render
Sign into https://dashboard.render.com/ and select New > Blueprint. Connect the GitHub repository and select render.yaml. Confirm the web service is **Free**; this blueprint does not create a paid database or disk.

Enter the prompted values:

| Render variable | Value |
|---|---|
| DATABASE_URL | Supabase Session pooler URI with SSL |
| AWS_ACCESS_KEY_ID | Supabase S3 access key |
| AWS_SECRET_ACCESS_KEY | Supabase S3 secret |
| AWS_S3_ENDPOINT_URL | Exact endpoint from Supabase S3 settings |
| AWS_S3_REGION_NAME | Exact Supabase project region |
| ADMIN_INITIAL_PASSWORD | Unique strong password, at least 12 characters |

The blueprint supplies the private bucket name, DEBUG=false, generated Django secret, review mode and HTTPS proxy settings. Render's assigned hostname automatically sets allowed hosts and the site URL. Leave SITE_URL unset for this free subdomain.

Apply the Blueprint. Build installs dependencies and collects static assets. Start applies migrations, creates initial settings and creates `clubadmin` once, then starts the server. Existing admin passwords are never overwritten. No interactive Render shell is needed.

Open the assigned HTTPS address and `/admin/`. Login as clubadmin. Remove ADMIN_INITIAL_PASSWORD from Render environment settings after the first successful login; save/redeploy. Use the admin password-change page for future changes. If the username was already present, bootstrap does not promote it or reset it.

In Site settings, add club information, approved privacy/refund text and membership requirements. Enable membership/contact when ready. Create review events and albums in admin; label invented demonstration content clearly. Enquiries and applications are saved in admin. Email sending is disabled for this review deployment: Render Free blocks standard SMTP and an HTTPS email integration is not included.

## 4. Stripe sandbox/test mode
The site can be reviewed before configuring payment. For checkout, add STRIPE_SECRET_KEY (`sk_test_...`) in Render. In Stripe's matching test environment, create a webhook for `https://YOUR-ASSIGNED-HOST/stripe/webhook/`. Subscribe to checkout.session.completed, checkout.session.async_payment_succeeded, checkout.session.async_payment_failed, checkout.session.expired and charge.refunded. Set STRIPE_WEBHOOK_SECRET to that endpoint's `whsec_...` signing secret. Redeploy.

Enable payments in site settings and create a bookable future event with a price. Test checkout using Stripe's test card 4242 4242 4242 4242, a future expiry and any three-digit CVC. Confirm the admin order becomes paid from the webhook. REVIEW_MODE rejects live secret keys. Never use real card details for test checkout.

## 5. Review acceptance checks
- Open homepage, calendar, gallery and membership on mobile and desktop.
- Create an event in admin; confirm its calendar date and download its .ics file.
- Upload a photo; restart/redeploy Render and confirm it still loads.
- Submit a synthetic membership application; verify it appears in admin.
- Complete a Stripe test payment and verify paid status; test cancellation and refund.
- Log out and confirm visitors cannot edit events or photos.
- Share only the public website URL; share the single admin credential privately if the client needs to test administration.

Free Render sleeps after 15 idle minutes; warm it before a demonstration. Supabase can pause after a week of inactivity. Free quotas apply; monitor the dashboards. Upgrade and complete production acceptance checks before taking real bookings. Backup/export review content before account deletion or migration.
